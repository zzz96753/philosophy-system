# 03 · 推理与部署优化

> 工程岗 + 算法岗都会问。核心是「显存、延迟、吞吐」三者的权衡。

---

## 一、自回归推理的两个阶段

- **Prefill（预填充）**：一次性处理整个 prompt，计算密集（compute-bound），可高度并行。
- **Decode（解码）**：逐 token 生成，每步只算 1 个 token，访存密集（memory-bound），是延迟瓶颈。

理解这个区分是很多优化的前提。

---

## 二、KV Cache

**问题**：自回归生成时，每生成一个新 token 都要对前面所有 token 重算 Key/Value，重复计算 $O(n^2)$。

**方案**：把已算过的 K、V 缓存起来，新 token 只算自己的 Q 并和缓存的 K、V 做注意力。计算从每步 $O(n)$ 重算降为复用。

**代价**：显存。KV Cache 大小 ≈ $2 \times L \times n \times d \times \text{batch} \times \text{精度字节}$（L 层数，n 序列长）。长上下文 + 大 batch 时 KV Cache 会吃掉大量显存，成为新瓶颈。

**相关优化**：
- **MQA（Multi-Query Attention）**：所有头共享一组 K/V，KV Cache 缩小 h 倍，略损质量。
- **GQA（Grouped-Query Attention）**：折中，几组头共享 K/V（Llama2-70B 用）。
- **PagedAttention（vLLM）**：像操作系统分页一样管理 KV Cache，减少碎片，提升吞吐。

---

## 三、量化（Quantization）

把权重/激活从 FP16 降到 INT8 / INT4，省显存、加速访存。

- **PTQ（训练后量化）**：直接量化已训练模型，快但可能掉点。代表：GPTQ、AWQ。
- **QAT（量化感知训练）**：训练时模拟量化，精度更好但成本高。
- **权重 vs 激活量化**：权重量化收益大且容易；激活量化难（有离群值 outlier）。
- **关键挑战**：激活中的离群值会放大量化误差，AWQ/SmoothQuant 等专门处理。

---

## 四、解码加速

- **投机解码（Speculative Decoding）**：用一个小模型快速草拟多个 token，大模型一次并行验证，接受正确前缀。在不改变输出分布前提下加速。
- **连续批处理（Continuous Batching）**：不同请求长度不一，动态拼批，提升 GPU 利用率（vLLM 核心特性）。
- **FlashAttention**：减少注意力的 HBM 读写，prefill 和长序列受益明显。

---

## 五、分布式与并行（训练侧也常考）

- **数据并行 DP**：每卡一份完整模型，分不同数据，梯度 all-reduce。
- **张量并行 TP**：把单层权重切到多卡（如把 FFN/注意力的矩阵按列/行切）。
- **流水并行 PP**：把不同层放不同卡，按 micro-batch 流水。
- **ZeRO（DeepSpeed）**：把优化器状态/梯度/参数分片到多卡，省显存，支撑超大模型。
- 实际大模型训练常是 **3D 并行（DP+TP+PP）+ ZeRO** 组合。

---

## 六、面试高频问答

**Q：为什么 decode 阶段是 memory-bound？** 每步只生成 1 个 token，计算量小，但要把全部权重 + KV Cache 从显存读进来，瓶颈在访存带宽而非算力。所以提升 batch（摊薄权重读取）能大幅提吞吐。

**Q：MQA/GQA 为什么有效且代价小？** 注意力的多样性主要来自多个 Q，K/V 共享对质量影响有限，却能成倍压缩 KV Cache，对长上下文/高并发收益巨大。

**Q：INT4 量化掉点严重吗？** 权重 INT4（如 GPTQ/AWQ）配合离群值处理，多数任务掉点很小；激活量化更激进时风险更高。

**Q：投机解码为什么不改变输出质量？** 大模型对草稿 token 做验证，只接受与自己分布一致的部分，数学上保证输出分布与原模型一致。

---

## 七、追问陷阱

- **「KV Cache 省了计算，那瓶颈转移到哪？」** → 显存容量和访存带宽。
- **「长上下文为什么难？」** → 注意力 $O(n^2)$ + KV Cache 线性增长，显存和延迟双重压力。
- **「TP 和 PP 各自的通信开销？」** → TP 每层都要通信（带宽敏感，适合机内 NVLink）；PP 在 stage 边界通信（适合跨机），但有流水 bubble。
- **「batch 越大越好吗？」** → 提吞吐但增显存和单请求延迟，需在 SLA 下权衡。
