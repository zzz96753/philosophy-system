## Q53 ★ 分层架构 vs 端到端：优劣与之争

- **分层（high-level 规划 + low-level 控制）**：
  - high-level：LLM/任务规划器把指令分解成子任务/技能序列。
  - low-level：技能库/控制器执行每个子任务。
  - **优点**：可解释、模块化、易调试、可复用技能、长程任务好处理。
  - **缺点**：模块间误差传递、接口僵硬、技能库需人工设计、上限受限于技能。
- **端到端（VLA 直接 观测→动作）**：
  - **优点**：联合优化无接口损失、可学到难以手工设计的行为、随数据 scale。
  - **缺点**：黑箱难调试、长程任务难、数据需求大、安全难保证。
- **之争核心**：分层泛化靠组合已有技能、落地稳；端到端泛化靠数据和 scaling、上限高但贵。
- **现状趋势**：**混合**——大模型出语义子目标（慢、低频），底层学习/控制做执行（快、高频），即 system2+system1（π0.5、Helix、Gemini Robotics 的思路）。

## Q54 ★ LLM 做任务规划的典型范式

| 范式 | 思想 | 代表 |
|------|------|------|
| **LLM 直接分解** | 让 LLM 把任务拆成自然语言子步骤 | zero-shot planner |
| **affordance grounding** | LLM 提议 + 价值函数判断可行性 | **SayCan** |
| **Code as Policies** | LLM 直接生成调用 API/技能的**代码** | Code as Policies |
| **ReAct** | 推理(reason)与行动(act)交替，可调用工具/感知反馈 | ReAct |
| **CoT/子目标推理** | 显式推理中间步骤再出动作 | RT-H, ECoT(具身思维链)|

## Q55 SayCan 的 affordance grounding

- **解决的问题**：LLM 懂语言但**不知道当前环境下什么动作可行**（可能规划出"去拿苹果"但周围没苹果，或机器人够不到）。
- **核心思想**：把决策拆成两部分相乘：
  - **Say**：LLM 给出每个候选技能与指令的**语义相关性** p(技能 | 指令)。
  - **Can**：价值函数/affordance 模型给出每个技能在**当前状态成功的概率** p(成功 | 状态, 技能)。
  - 选 **二者乘积最大** 的技能执行。
- 意义：把 LLM 的"知识"和机器人的"现实能力"结合——既相关又可行。

## Q56 ☆ 长程任务为什么难？如何分解

- **难点**：
  - 步骤多→复合误差累积，一步失败全盘崩。
  - 稀疏奖励/延迟反馈，credit assignment 难。
  - 需要记忆和子目标管理。
- **解法**：
  - **分层分解**：LLM 把长任务拆成子目标，逐个完成（任务与运动规划 TAMP）。
  - **技能复用**：训练可组合的原子技能。
  - **闭环重规划**：每步后检查状态、失败则重规划（ReAct/反馈）。
  - **记忆/状态跟踪**：维护任务进度。

## Q57 控制/感知/规划频率不一致如何协调

- 典型频率：底层力控/电机 **500Hz~1kHz**，感知 **30Hz**，大模型规划 **1~10Hz**。
- **协调机制**：
  - **分层异步**：各层独立频率运行，高层低频出目标，低层高频跟踪。
  - **action chunking**：大模型一次出一段动作，低层高频回放。
  - **插值/滤波**：把低频目标平滑插值到高频指令。
  - **实时性保证**：控制回路放实时线程/RTOS，大模型推理异步不阻塞。

## Q58 ◆ 端到端 VLA vs "LLM 规划+技能库"，赌哪个走向通用（开放题）

> "短期我赌**混合架构**，长期看好**端到端但分层结构化**。
> - LLM规划+技能库**现在更落地**：可解释、可复用、长程稳，工业部署友好；但上限受技能库限制，接口僵硬，难处理需要紧耦合感知-动作的灵巧操作。
> - 端到端 VLA **上限更高**：能学到手工难设计的灵巧行为，随数据 scaling；但当前数据不足、长程弱、难调试安全。
> - 我的判断：会收敛到**端到端学习的技能 + 大模型做高层语义规划**的分层混合（system1/system2），既享受 scaling 又保留可控性。纯符号规划会被淘汰，纯单体端到端短期难独自搞定长程。关键变量是**数据规模**——数据够了端到端占比会越来越大。"
